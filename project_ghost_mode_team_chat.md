**What it is:** agency/client team members get a PRIVATE internal thread (`conversation_kind = 'job_team_internal'`) to discuss a mission among themselves — admin is NOT a visible participant. **The twist (Ghost Mode):** the Platform Super Admin (ebi, god-mode) has HIDDEN read-only access for platform integrity/safety monitoring. The team must NOT see the admin in the room, in the member list, or in any "seen by" indicator, and must not be able to tell the admin is reading.

**Contrast with existing team chat:** the current team chat IS the SHARED `job_client_admin` buyer↔admin thread (admin visibly present). Ghost Mode is the opposite: private FROM the admin's visible presence, but silently readable BY the admin. Don't conflate the two `conversation_kind`s. See [[reference_master_feature_matrix]] §Team-chat-mechanics and migrations 184000/186000.

**Architecture sketch (to design in the Epic):**
- Add enum value `job_team_internal` to `conversation_kind`; conversation owned by the principal (`user_id = COALESCE(agency_id, client_id)`), keyed to `job_id`.
- RLS: team SELECT+INSERT via an `nx_can_team_access/manage` variant scoped to this kind (post = non-viewer roles). Admin gets a **SELECT-only** god-mode overlay — **never INSERT** (an admin message would break the ghost).
- **Ghost integrity = the hard part:** every participant/member/"seen-by" projection and the notification fan-out must EXCLUDE the admin. Audit the UI member-list query + `tg_notify_messages` so admin presence never leaks. Admin read should ideally be logged to the audit trail (admin-only) for accountability.
- Open decisions: (a) is the ghost read itself audit-logged? (b) any monitoring-disclosure/consent copy needed in ToS for legal cover? (c) does Ghost Mode apply to ALL `job_team_internal` rooms by default, or toggled per-investigation?
