# NEXPEC — iOS `ReactCodegen` / NitroModules Build Fix

**Date:** 2026-05-29
**Symptom:** iOS build fails at `PhaseScriptExecution` → `ReactCodegen`, surviving every deep clean (DerivedData, watchman, `node_modules`, `prebuild`).

---

## Root cause (proven, not guessed)

The React Native **New Architecture was OFF at the native build level** even though
`app.config.js` declares `newArchEnabled: true`.

Evidence collected from the live tree:

| Check | Found | Expected |
|---|---|---|
| `ios/Podfile.properties.json` → `newArchEnabled` | **missing key** | `"true"` |
| `android/gradle.properties` → `newArchEnabled` | **`false`** | `true` |
| `ios/Pods/ReactCodegen` | **absent** | present (New-Arch codegen) |
| `ios/Pods/NitroModules`, tflite/skia pods | **absent / unlinked** | linked |
| `react-native-fast-tflite` | `3.0.1` (Nitro, built vs `nitrogen ^0.35.2`) | — |
| `react-native-nitro-modules` | `0.35.9` ✅ satisfies `^0.35.2` | — |

The Podfile derives the build flag straight from that file:

```ruby
ENV['RCT_NEW_ARCH_ENABLED'] = podfile_properties['newArchEnabled'] == 'true' ? '1' : '0'
```

With the key absent it evaluated to **`0`**. `react-native-fast-tflite@3` is a
**NitroModules** library and `@shopify/react-native-skia` is a **Fabric** renderer —
both *require* New Arch. Under Old Arch, nitrogen's generated C++ hits
`#error NitroModules cannot be found!` and the `ReactCodegen` script phase aborts.

**Why clean rebuilds didn't help:** the version pins were never the problem
(`0.35.9` satisfies what `fast-tflite@3.0.1` was built against). The bad state lived
in the *generated* property files. `expo-build-properties@0.13.3`'s `newArchEnabled`
option is a **no-op on SDK 52** (New Arch graduated to the top-level config key), so
setting it there silently did nothing, and a non-`--clean` prebuild won't rewrite an
existing `Podfile.properties.json`.

---

## The fix (applied in this repo)

1. **`plugins/withNexpecNewArch.js`** — a config plugin that **forces**
   `newArchEnabled` into `ios/Podfile.properties.json` *and* `android/gradle.properties`
   on **every** prebuild. New Arch is now self-healing; it can never silently regress.
   Registered **last** in `app.config.js` so it has the final say.

2. **`app.config.js`** — registered `react-native-fast-tflite`'s own config plugin
   (`enableCoreMLDelegate: true` → GPU/Neural-Engine inference on iOS) and the guard
   plugin above.

3. **On-disk files corrected now** (for an immediate build without waiting on prebuild):
   `ios/Podfile.properties.json` → `"newArchEnabled": "true"`,
   `android/gradle.properties` → `newArchEnabled=true`.

## Rebuild sequence (run on your Mac)

```bash
# from repo root
watchman watch-del-all 2>/dev/null || true
rm -rf ios android                         # CNG: regenerate natives from config
rm -rf "$TMPDIR/metro-"* "$TMPDIR/haste-map-"* node_modules/.cache

npm install                                # ensure nitro 0.35.9 + tflite 3.0.1 present

npx expo prebuild --clean                  # guard plugin writes New Arch into both files

# ── VERIFY New Arch actually landed (must print true / true) ──
node -e "console.log('ios:', require('./ios/Podfile.properties.json').newArchEnabled)"
grep '^newArchEnabled' android/gradle.properties

# ── Install pods with New Arch explicit (belt-and-suspenders) ──
cd ios && RCT_NEW_ARCH_ENABLED=1 bundle exec pod install && cd ..
#   no bundler?  →  RCT_NEW_ARCH_ENABLED=1 npx pod-install

# ── VERIFY codegen + native pods linked ──
ls ios/Pods/ReactCodegen >/dev/null 2>&1 && echo "ReactCodegen ✓"
ls -d ios/Pods/NitroModules >/dev/null 2>&1 && echo "NitroModules ✓"
grep -iE "NitroTflite|tflite|skia" ios/Podfile.lock

npx expo run:ios                           # or open ios/*.xcworkspace in Xcode
```

> Because `prebuild --clean` regenerates `ios/`, it overwrites the manual edit in
> step 3 — **but the guard plugin re-applies it**, which is exactly why the verify
> step above will still print `true`.

## Secondary hardening (only if `ReactCodegen` still can't find `node`)

`ios/.xcode.env` ships `export NODE_BINARY=$(command -v node)`. Xcode's script phase
runs a **non-login shell that never sources nvm**, so for nvm installs that resolves to
empty and RN falls back to a hardcoded path in `ios/.xcode.env.local` — which **breaks
whenever your active node version changes**. If you hit a `node: No such file or
directory` style failure, replace `ios/.xcode.env.local` with a version-agnostic loader:

```bash
# ios/.xcode.env.local  (user-owned, not regenerated by prebuild)
export NVM_DIR="$HOME/.nvm"
[ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh" >/dev/null 2>&1
export NODE_BINARY="$(command -v node)"
```

This survives nvm upgrades — no pinned `v20.20.0` path to rot.

---

## Why this is bulletproof going forward

The guard plugin runs inside the prebuild pipeline itself, so the New-Arch flag is
re-asserted on every `expo prebuild` / EAS build. Combined with the top-level
`newArchEnabled: true`, there is no longer any path where the native project drifts
back to Old Arch and silently breaks Nitro/Skia codegen.
