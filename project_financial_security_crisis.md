**CRITICAL pre-launch finding (final QA sweep).** The NEXPEC mobile money stack let ANY user credit their own wallet balance:

1. `app/(inspector)/wallet/withdraw.tsx` — a shipped "+$5000" cheat button (`handleCheatDeposit`) did `wallets.upsert({ available_balance: balance+5000 })`. **REMOVED** (button + handler). Also fixed `validateForm` `wallet?.balance || 5000` → `|| 0`.
2. `src/shared-ui/modals/AddFundsModal.tsx` — a real "Top Up" feature did `wallets.update({ balance: balance + amount })` against a fake "•••• 4242 (Demo)" card with NO payment. **NEUTRALIZED**: handler now fails closed ("Top-up unavailable / contact support"); removed the client balance write + unused supabase import.

**ROOT CAUSE — NOW LOCKED (user supplied live schema; migration `supabase/migrations/20260719120000_financial_lockdown.sql` built).** wallets had RLS effectively open (12 cols incl BOTH `balance` and `available_balance`; transactions 18 cols w/ `amount` numeric + `*_halalas` int8 + `reference_id`; job_expenses 8 cols w/ client-settable `id` PK). The migration: (1) versions all 3 tables CREATE TABLE IF NOT EXISTS (no-op on prod, baseline for fresh builds; FKs omitted to avoid ordering fails); (2) adds `transactions.client_op_id` + partial unique index; (3) wallets RLS ENABLE + drop-ALL-policies (DO loop over pg_policy) + owner-SELECT-only + REVOKE writes → balance mutable ONLY via SECURITY DEFINER RPC (owner bypasses non-forced RLS); (4) transactions same lock (ledger server-write-only); (5) job_expenses inspector-owns + job-parties read + admin; (6) DROP+CREATE `process_withdrawal(numeric,jsonb,text)` — atomic (FOR UPDATE), idempotent (p_client_op_id check AFTER the lock = race-safe), sets the NON-NULL *_halalas (= ROUND(amt*100)) the old body omitted (old 2-arg DROPped so the non-idempotent overload can't be called). **NOT pushed yet → user must `supabase db push`.** withdraw.tsx + expenses.tsx now route through the outbox (`withdrawal_request`/`expense_add` kinds; withdraw awaits flush + reads getOpStatus for success/queued/failed; expense idempotent on client PK + deferred receipt upload).
