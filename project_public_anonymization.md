Inspector payout is a platform-set % of each job, so any exposed inspector identity lets a client bypass NEXPEC and contract directly. Therefore ALL public inspector surfaces are pseudonymous **at the data layer** (not just the UI — UI hiding is bypassable via network/API). Shipped 2026-06.

**Three public surfaces, all anonymized:**
- `/p/[userId]` (apps/web) — Trust Card. Reads `fetchInspectorTrustCard` (PII-free column subset). No name/photo/bio/headline; coarse region only.
- `/inspectors` — directory listing. Same anonymized view; cards show handle + sigil; filter = region/specialty/rating/verified; NO name search, NO A-Z sort.
- `/passport/[sealId]` — verifiable seal. RPC returns inspector_id (not name); shows handle + cross-link.

**Enforcement (data layer):**
- View `public.inspectors_directory` rewritten to emit ZERO PII — migration `20260727120000_anonymize_inspectors_directory_view.sql` (drops full_name/headline/bio/avatar_url/location_city; keeps opaque id + province + competencies + metrics). Eligibility still filters on full_name presence but never SELECTs it.
- RPC `get_inspection_passport` returns `inspector.id` not name — migration `20260726120000`. shared-core `passport` contract: `inspector: { id }`.
- Public reviews: `fetchReviewsForUser` drops the reviewer name/email join → ReviewCard shows "Verified client". (`fetchReviewsForJob`, authenticated, KEEPS identity — that's intentional.)

**Identity layer:** `apps/web/src/lib/identity/inspectorHandle.ts` (deterministic non-reversible `NX-XXXXXX` handle + on-brand gradient from the UUID) + `apps/web/src/components/trust/TrustSigil.tsx` (generated SVG avatar, $0, no photo).

**RULES for future work:** (1) NEVER select/return inspector PII (name, photo, bio, headline, city, email, contact) on any anon/public surface — add only PII-free columns to the view. (2) Capability is platform-VOUCHED (verified competencies = specialties/ndt_methods/certifications reframed as "NEXPEC-Verified"), never a raw CV/degree/country-doc (avoids bias too). (3) Engagement is admin-brokered + escrowed only ("Request through NEXPEC" CTA) — reinforces [[project-golden-rules]]. (4) The opaque UUID id is NOT PII (routing + brokered-hire ref) and may be exposed.

**SUPPLIERS now anonymized too (2026-06-05, same anti-poaching principle).** ebi flagged that the Find Suppliers directory leaked supplier legal names while brokered offers showed only an NX- handle. Migration `20260801123700_anonymize_supplier_directory.sql`: (1) `supplier_directory` view drops `legal_name` + `headline` (emits opaque id + capabilities + standards + rating + country + verified only); (2) `supplier_profiles` RLS `supplier_read` tightened to `id = auth.uid() OR nx_is_admin()` (removed public `is_active` read → buyers can't read the name from the base); (3) `supplier_match()` (returns legal_name) REVOKEd from authenticated/anon, GRANTed to service_role. Web `/directory` + `/directory/[id]` and mobile `app/suppliers/index.tsx` now render `nxHandle(id)` + TrustSigil (web) / storefront icon (mobile); search matches handle/capabilities, not name. New role-neutral handle: web `nxHandle` alias in `lib/identity/inspectorHandle.ts`; mobile `src/core/utils/handle.ts` (byte-identical FNV-1a+Crockford algo so handles match across platforms). NOTE: the brokered-offer handle (`rfq_client_offers_view`, sha256-based) and the directory handle (FNV-based) intentionally DIFFER so a buyer can't correlate an offer to a directory supplier. **GOD-MODE UPDATE 2026-06-05 (commit fa74d1f, migration `20260801123800_admin_sees_supplier_identity.sql`):** ebi flagged that the directory showed the NX- code even to him (admin = full control of everything, see [[feedback_god_mode_admin]]). So the earlier "view drops legal_name/headline for everyone" is SUPERSEDED: `supplier_directory` now emits `legal_name` + `headline` via `CASE WHEN public.nx_is_admin() THEN s.legal_name ELSE NULL` — real identity to admin, NULL to clients/agencies/enterprises/anon (anti-poaching preserved BY CONSTRUCTION; the CASE can't leak to non-admin). Web `/directory`(+`/[id]`) and mobile `app/suppliers/index.tsx` render `legal_name?.trim() || nxHandle(id)` (font-mono only for the handle), and search matches the real name when present. **REVISED RULE for suppliers:** the directory is zero-PII to non-admin, REAL identity to `nx_is_admin()` — do NOT strip the admin-gated `legal_name`/`headline` columns thinking they're a leak. (The inspector surfaces above remain fully anonymized to everyone, incl. admin, on the *public* `/p`,`/inspectors`,`/passport` routes; admin reads inspector identity through admin tooling, not those public views.) Commits 535cd29 + 6f2230e (initial anon) + fa74d1f (god-mode). Related: [[project_admin_intercept_markup]], [[feedback_god_mode_admin]].

**AUTHENTICATED client surfaces — IDENTITY ESCROW with a REVEAL BOUNDARY (confirmed by ebi 2026-06-06).** Beyond the public surfaces above, the *logged-in client* must also see only `nxHandle(id)` + sigil for an inspector during PRE-HIRE (applications, dispatch/shortlist, contract sign) AND ACTIVE-WORK (assigned, in-progress). The real name is revealed to the client ONLY AFTER the reveal boundary = **final report sign-off / job completion** (`admin_confirmed_at` set OR job `status='completed'`). Post-reveal surfaces (rating, final-report review, completed reports, budget/invoices/payment records) intentionally show the real name — do NOT anonymize those. The canonical reveal-aware view is `client_assigned_inspector_view` (gates `inspector_legal_name` on `admin_confirmed_at`/`identity_revealed_at`); mirror that gate in any new client fetcher.
